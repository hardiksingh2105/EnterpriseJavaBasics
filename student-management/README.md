# Student Management System — Labs 4–7

Final cumulative Spring Boot application for the Enterprise Java laboratory. It uses Java 17, Spring Boot 4.2.0, Spring MVC, Spring Data JPA, Hibernate, Bean Validation and PostgreSQL. This project is independent of the in-memory Lab 2 and Lab 3 folders.

## Features

- PostgreSQL-backed Student CRUD with manually supplied positive IDs.
- Derived searches by exact name, partial name and email.
- Pagination (`Pageable`) and name sorting.
- One-to-many Student–Course association with cascade delete.
- Field-level request validation and centralized exception handling.
- IntelliJ HTTP Client requests under `requests/student-management.http`.

## Requirements

- JDK 17 or newer (the Maven compiler release is 17).
- Maven 3.6.3 or newer.
- PostgreSQL 18.7 or a compatible PostgreSQL 18 server.
- Environment variable `DB_PASSWORD` containing the local `postgres` user's password.

## Database setup

```sql
CREATE DATABASE studentdb;
```

Connect:

```powershell
psql -U postgres -h localhost -p 5432 -d studentdb
```

Set the password for the current PowerShell session:

```powershell
$env:DB_PASSWORD = "your_local_postgresql_password"
```

Or add `DB_PASSWORD` to the IntelliJ run configuration's environment variables. `.env.example` is a template only; Spring Boot does not automatically load a plain `.env` file. Never commit an actual password.

## Run

```powershell
mvn clean test
mvn spring-boot:run
```

The service runs at `http://localhost:8081`. Hibernate creates or updates the `students` and `courses` tables; it does not create the `studentdb` database itself.

## API reference

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/hello` | Greeting |
| GET | `/student` | Predefined Rahul sample (not persisted) |
| GET | `/students` | All persisted students |
| POST | `/students` | Create student |
| GET | `/students/{id}` | Student by ID, including courses |
| PUT | `/students/{id}` | Update name/email |
| DELETE | `/students/{id}` | Delete student and associated courses |
| GET | `/students/search/name/{name}` | Exact name query |
| GET | `/students/search/name/contains/{keyword}` | Partial name query |
| GET | `/students/search/email/{email}` | Email query |
| GET | `/students/page?page=0&size=2` | Paginated students (size 1–100) |
| GET | `/students/sort/name` | Ascending name sort |
| GET | `/courses` | All courses |
| POST | `/students/{studentId}/courses` | Add course to student |

Example student request:

```json
{
  "id": 101,
  "name": "Neha",
  "email": "neha@example.com"
}
```

Example course request:

```json
{
  "courseName": "Enterprise Java",
  "credits": 4
}
```

## Validation and errors

Student ID must be positive, name and email must be nonblank, and email must have a valid format. POST and PUT both use `@Valid`. The advice class returns field-keyed validation errors with HTTP 400, missing students with HTTP 404, duplicate IDs with HTTP 409, and invalid path/body or pagination values with HTTP 400.

## HTTP Client tests

Open `requests/student-management.http` in IntelliJ IDEA and execute its requests in order. The first two optional DELETE requests clean up demonstration IDs from a previous run. The remaining requests create/update/search/page/sort students, add a course, test invalid and valid POST/PUT requests, request a missing record and verify cascade deletion.

## PostgreSQL verification

```sql
SELECT * FROM students;
SELECT * FROM courses;

SELECT c.id, c.course_name, c.credits, c.student_id, s.name, s.email
FROM courses AS c
JOIN students AS s ON s.id = c.student_id;
```

The relationship's foreign-key column is `courses.student_id`. Student IDs are assigned by the client; course IDs are generated by PostgreSQL using identity generation.

## Design notes

The application follows Controller → Service → Repository → PostgreSQL. Controllers handle HTTP concerns, services enforce business rules and transactions, repositories handle persistence, DTOs define validated request input, and entities model the database. `@JsonManagedReference` on Student and `@JsonBackReference` on Course avoid JSON recursion while allowing Student responses to include their courses.
